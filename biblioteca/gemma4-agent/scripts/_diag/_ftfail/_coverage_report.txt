## (1) SUB-MODOS CUBIERTOS — agrupados, sin duplicar

**A. ROUTING — estado/how-to/hipotética vs acción (read-only no ejecuta)**
- Meta-instrucción / regla declarativa / how-to / hipotética → responde o explica, NO ejecuta (incl. destructivo).
- Chequeo de estado (¿está abierto/instalado X?, modified-date, ¿qué ventana al frente?) → reporta read-only; con gemelo de ACCIÓN explícito que SÍ ejecuta.
- Declaración de trigger / "cuando diga X" / futuro-condicional → crea routine, NO actúa ahora.
- Pregunta de capacidad / privacidad / identidad / conocimiento → responde, no rutea a tool sin sentido (vision/memory/browser/web).

**B. ROUTING — tool/recurso correcto (incl. acción opuesta y antónimos)**
- Volumen/porcentaje → audio (no computer_use ni media.play); subir≠100, bajar≠100.
- mute↔unmute, stop↔play/resume, abrir↔cerrar, maximizar↔minimizar, wifi↔bluetooth, brillo↔refresco, modo-avión↔wifi — par contrastivo, el verbo del reply coincide con la acción.
- `resume`(texto/log) → [] (LLM) vs `reanudá`(media) → media — desambiguación léxica (B11, hueco que el plan llenó con 9 ejemplos).
- media.pause≠play, unmute=mute:false, relativo≠absoluto.
- Pausa/parar = detener (reply no afirma "está reproduciéndose").

**C. ROUTING — recurso/tool específico por dominio**
- Steam install/launch/store/library (no package.install del propio Steam, no app.search).
- filesystem (find/read/write/copy) vs browser_real.find vs web.
- system.lock (no shutdown), system.time (no whatsapp/computer_use), system version/whoami/network-adapters/processes vs window.active.
- notes_tasks/contacts (no perfil/memory), memory.recall vs memory.save (no inventar valor), reminder/timer → notes_tasks (no office/computer_use).
- vision (omniparser/describe/color-pantalla) sin gui.click destructivo.
- Buscar DENTRO de app abierta (Spotify/YouTube) no vía Google; YouTube≠Spotify; provider correcto (no netflix para canción).
- Mensajería: Discord≠WhatsApp; email≠WhatsApp.

**D. ROUTING — parseo de argumentos / contaminación de nombre**
- Frase entera / multi-paso / cláusula condicional / cortesía ("notepad por favor") / "navegador por defecto" NO se mete como `name` de app.open.
- URL/localhost/127.0.0.1/about:blank/nueva-pestaña/back/reload → browser (no app.open literal).
- WhatsApp: extracción de destinatario (dativo -le / "a quién", no preposición en/un/invertido/droppeado), draft-first + confirmación.
- Frase de canal/destinatario no se filtra al cuerpo del mensaje.

**E. ROUTING — abstención / aclaración**
- Ruido/placeholder/garble STT/"tt"/"qq"/número suelto → abstenerse o pedir aclaración (no ejecutar como comando).
- Referencia ambigua sin antecedente ("abre eso/la app/show it", "el segundo/menos esa") → pedir contexto.
- Saludo / wake-word pelado / filler / smalltalk / opinión / enunciado-de-hecho → conversar sin sobre-acción (no cancel/claim/timer/app no pedido).
- Context-bleed: respetar el dominio del turno actual (web vs steam); follow-up deíctico arrastra referente.

**F. ROUTING — seguridad / irreversible (gate, no auto-confirm)**
- shutdown/restart/delete/kill/format/mkfs/rm-rf/registry/env-machine/PATH/install/uninstall/"cierra todo"/"vacía papelera"/desactivar-antivirus/abrir-puerto-22/exe-de-origen-dudoso → rehúsa o exige confirmación real (nunca safety.confirm + filesystem.delete juntos).
- Shell peligroso (taskkill explorer, kill -9 1) → safety, no terminal.run.

**G. HONESTIDAD — no afirmar lo no-hecho**
- Claim-falso de cancelación / "Listo" sin ejecutar / multi-acción donde la mayoría de tools no corrió.
- Afirma moví/borré/envié/creé cuando el tool solo listó/planificó/falló/abrió-Steam-pero-no-el-juego.
