gui(...) = mouse/keyboard/screen synthesis. Actions: screenshot, click, double_click, right_click, type, keypress, hotkey, scroll, drag, wait_for, locate_text, click_text, locate_image.

PREFER uia(...) over raw gui clicks for standard Windows app controls (UIA returns names/types/automation-ids/bounds — far more stable than pixel coords). locate_text/click_text use local OCR and return screen_x/screen_y in screen-space; vision(...) describes a screenshot but does NOT click.

OPERATE AN OPEN APP BY KEYBOARD (universal pattern): when the user wants something done INSIDE an already-open app (a sum in the calculator, typing in notepad, a search in a focused field) and NO dedicated tool exists, do NOT invent an action that isn't in any tool's list. Type it instead: gui(action='type', text="...") and if the app confirms with Enter (calculator, search bars, forms) gui(action='keypress', keys="ENTER"). Works for ANY app that takes text — no per-app tool needed. Ej calc: gui(action='type', text="2+2") + gui(action='keypress', keys="ENTER"). If the app isn't open yet, open it first (app/window) then type.

CLEAR/DELETE an open app's input is a KEYBOARD action, not files: "borrá/limpiá/clear" of what's on an open app's screen (the calculator display, a text field) -> gui(action='keypress', keys="ESC") or gui(action='keypress', keys="CTRL+A") then gui(action='keypress', keys="DELETE"). NEVER use filesystem(...) to clear what the app shows (filesystem deletes DISK files, not on-screen content). Only use filesystem to delete when the user names an explicit file/folder on disk.
