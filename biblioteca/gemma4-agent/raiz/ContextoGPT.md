Y que va a pasar cuando algo no necesite una tool?
Pregunta clave, y toca un punto de diseño importante que debo explicarte con honestidad.

Qué pasa hoy (con el entrenamiento actual)
Al sacar la abstención, FunctionGemma quedó entrenado para SIEMPRE emitir una llamada. Entonces, si le mandás algo que no necesita tool ("hola", "gracias", "quién descubrió América", "contame un chiste"), va a forzar una llamada igual (alucina la tool más cercana). Eso es over-calling.

Por qué en tu arquitectura quizás no importa
En Baxy el flujo es: router decide → si es intención de tool, manda a FunctionGemma; si es charla/conocimiento, va al LLM conversacional (no a FG). O sea, el router es el "portero" y FG nunca debería recibir un input sin-tool. Si el router filtra bien, el problema no aparece.

El riesgo
Los routers no son perfectos. Si alguna vez le llega a FG un input sin-tool (router falla, o lo invocás directo), va a inventar una llamada.

La solución correcta (NO la que rompió)
La abstención que usé (target vacío) fue un error doble: envenenaba con EOS temprano y era una mala señal. La forma correcta de darle a FG la capacidad de "no hacer nada" es una tool centinela — ej. una tool no_tool / chat que FG llama cuando nada aplica, y el orquestador la interpreta como "pasale esto al LLM conversacional". Eso le da el abstenerse sin el envenenamiento (emite algo concreto, no EOS).
