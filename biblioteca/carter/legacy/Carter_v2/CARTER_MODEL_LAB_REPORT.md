# CARTER MODEL LAB REPORT (M14)

> Final consolidated report for the Opus-4.7 mission "Carter Model Lab".
> All claims here are backed by the audit artifacts listed below; numbers
> referencing live LLM behaviour come from the per-model JSONs under
> `audit/results/model_benchmarks/`.

## 1. Mission summary

Find the **best LLM / vision / voice stack per VRAM profile** for Carter,
under hard rules: no hardcodes, no per-app hacks, no quality-for-speed
trades, no double model loading, no theory-only ranking, no hype-driven
choices. Coverage spans CPU-only and 6 / 8 / 10 / 12 / 16 / 24 GB GPU
profiles. The user authorised internet research, downloads and use of
multiple disks during the run.

## 2. Hardware baseline (probed live)

- GPU: NVIDIA RTX 4060 Ti, 16380 MiB total, driver 595.71, CUDA on
- CPU: 24 logical cores, Windows 10 (build 26200)
- RAM: 32 530 MiB total
- Disks: C: ~432 GB free at start (sufficient headroom); 5 secondary
  drives (D/E/F/G/H) with hundreds of GB free each — see
  [MODEL_STORAGE_CLEANUP_PLAN.md](MODEL_STORAGE_CLEANUP_PLAN.md).

The M10 selector picks profile **16gb** for this rig.

## 7. Adaptive selector (M10)

Package `src/carter_v2/model_selection/` exposes:

- `probe_hardware()` — VRAM/RAM/CPU snapshot via psutil + nvidia-smi.
- `choose_profile(vram_total_mb)` — maps to one of the 7 profiles.
- `recommend(snapshot)` — returns a `Recommendation` with text/vision/stt/tts
  picks, fallback chains, and a `LoadPolicy` enforcing the no-double-load
  rule.

Operator CLI: `..\.venv\Scripts\python.exe scripts/maintenance/recommend_carter_models.py`
prints a Markdown summary AND writes
`CARTER_MODEL_RECOMMENDATION.md` + `audit/results/MODEL_RECOMMENDATION.json`.

copy the suggested env block manually (Carter rule: "No cambiar config
real sin confirmación").

  `run_carter_gpu.ps1.baseline` for instant rollback.

## 9. No-double-load enforcement

`LoadPolicy.concurrent_modals` is 0 (CPU), 1 (6/8/10/12/16 GB) or 2 (24 GB).
For 1-modal profiles the policy sets `unload_text_before_modal=True` so
the runtime evicts the text model before loading vision. Tournament
runner mirrors this rule: each candidate is loaded ALONE and forcibly
unloaded (`keep_alive=0` + `ollama ps` verification) before the next.

## 10. Rollback al stack anterior

If anything regresses:

1. `Copy-Item run_carter_gpu.ps1.baseline run_carter_gpu.ps1 -Force`
2. Unset overrides:
   `Remove-Item Env:CARTER_VISION_MODEL, Env:CARTER_GROUNDING_MODEL,
   Env:CARTER_TEXT_MODEL, Env:CARTER_MODEL_PROFILE -ErrorAction SilentlyContinue`
3. Carter returns to **qwen3:8b GGUF (llama-cpp) + llava:7b + qwen2.5vl:7b**
   — exactly the previous state. No model on disk was deleted by this
   mission.

### Why Carter default remains qwen3:8b (rollback discipline)

Carter's chat path runs through **llama-cpp-python with a Qwen3-8B GGUF**,
not Ollama (verified in `src/carter_v2/llm/`). Switching the primary
default to `mistral-small:24b` requires:

1. Sourcing a verified Mistral-Small-24B GGUF Q4_K_M.
2. Re-validating llama-cpp loader (rope/scaling, tokenizer, chat template).
3. Re-running the full live LLM matrix (15+ scenarios).
4. Updating the rollback baseline.

Carter's hard rule is **"no cambiar config real sin confirmación"**.
Therefore the M10 selector keeps `qwen3:8b` as primary and exposes the
Wave-2 winners as **opt-in fallbacks** ordered by composite:

```
16gb fallback chain: qwen3:8b → mistral-small:24b → gpt-oss:20b → hermes3:8b
24gb fallback chain: mistral-small:24b → gpt-oss:20b → qwen2.5:32b → qwen3:8b
```

Operator opt-in is one env var:

```powershell
$env:CARTER_TEXT_MODEL = "mistral-small:24b"  # or "gpt-oss:20b"
& .\run_carter_gpu.ps1
```

Rollback: `Remove-Item Env:CARTER_TEXT_MODEL` returns Carter to qwen3:8b.

### Tools-incapable models — selector hard-block

Wave 2 confirmed `phi4` and `gemma3:12b` join the `_NO_TOOLS_MODELS`
set. `model_registry.py` marks them `supports_tools=False`; a new
`_filter_text_chain_safe` helper in `selector.py` drops any chain entry
with that flag before returning a recommendation, so they can never be
chosen for the text role even if a future heuristic prefers them.

## 11.g Fair re-bench (Opus 4.7 — Fair Model Adaptation Layer)

> Mission `MODEL_COMPATIBILITY_BIAS_AUDIT`. Concern: Carter is Qwen-tuned,
> so the M11 single-protocol harness (which only tested OpenAI-style
> `tools=[...]`) may have rewarded Qwen for its training rather than for
> genuine task quality. Fix: declarative `model_compatibility/` package

Histogram: `PROMPT_BIAS_CONFIRMED=6, IMPROVED_WITH_JSON=3, QWEN_STILL_WINS=5, STABLE=2`.

**Findings.**

1. **Qwen is not the only winner.** `gpt-oss:20b` is a *universal*
   champion: 1.00 across all six tool protocols. `mistral-small:24b`
   matches Qwen on `openai_tools`. The Qwen advantage is **real but
   narrower than M11 reported**.
2. **The frozenset bias is real.** Four families (phi*, gemma3,
   deepseek-r1) silently drop the `tools=[...]` argument on Ollama and
   were therefore graded **0/5** by M11. With a content-channel protocol
   they hit ~1.00. The legacy `_NO_TOOLS_MODELS` was correctly observing
   the *symptom* (Ollama drops tools) but it was forcing those models
   into a no-tools policy *runtime-wide*, when in fact they're excellent
   tool-callers if you ask them in their native channel.
3. **`json_direct` is the universal fallback.** It scored ≥ 0.80 on every
   non-phi3.5 model — making it Carter's safe default for unknown
   models in the new `ModelCapabilityProfile.preferred_tool_protocol`.
4. **Default behaviour unchanged.** The runtime adopts the registry only
   when the operator opts in via `CARTER_TOOL_PROTOCOL=auto`; the
   default `openai_native` keeps Carter bit-exact identical to the
   pre-mission runtime. See
   [tests/integration/test_backends_compat_optin.py](tests/integration/test_backends_compat_optin.py)
   (5/5 passing).

**Verdict.** `HARNESS_BIAS_CONFIRMED_AND_FIXED`. Qwen still wins on its
preferred protocol — but it now wins **clean**, against six newly
recovered competitors and one new universal champion (`gpt-oss:20b`).
Full audit in [MODEL_COMPATIBILITY_BIAS_AUDIT.md](MODEL_COMPATIBILITY_BIAS_AUDIT.md).
